## Registro de incidente

Incluir número de caso, empresa y sucursal, fecha/hora, versión, pantalla, usuario sin contraseña, pedido afectado, pasos realizados, resultado esperado y resultado real. Adjuntar captura con datos innecesarios ocultos. Indicar si el negocio puede seguir operando y si se intentó repetir una venta.

Nunca adjuntar contraseñas, tokens o copias completas de la base en el reporte inicial. Si se necesita acceso técnico, acordar un canal y una cuenta temporal apropiados.

## Procedimiento

1. Registrar el incidente y confirmar recepción según canal acordado.
2. Determinar impacto y si existe una operación parcialmente registrada.
3. Conservar evidencia; evitar reintentos de venta sin conciliación.
4. Aplicar corrección o solución temporal autorizada por responsable.
5. Verificar datos y operación con el usuario.
6. Documentar causa, cambio, versión, evidencia y cierre.

## Contingencia

El negocio debe aprobar cómo registrar pedidos si el sistema queda fuera de servicio, quién custodia ese registro y cómo se conciliará después. No existe modo sin conexión identificado en la versión revisada. Registrar hora e identificador temporal y comprobar que no se duplique una venta cuando se restablezca el servicio. El procedimiento final debe adjuntarse al acta.
